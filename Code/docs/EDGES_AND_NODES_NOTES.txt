BOSTON INFLUENZA GNN — NOTES ON GRAPH EDGES, ANCHOR NODES, AND EVALUATION
Last updated: 2026-07-07

This file documents the GRAPH DESIGN for the Boston neighborhood-level influenza
GNN: the EDGE TYPES, the SURROUNDING-AREA ANCHOR NODES, the TEST-WINDOW / SEASON
split, and the RESULTS.

STATUS: the notebooks this file originally described are frozen in
Code/notebooks/ and superseded by the scripts in Code/. Section 1 maps the old
notebook names onto the new experiment names. Sections 2-7 (node structure, edge
types, weighting, seasons) still describe the live implementation in
influenza/graphs.py and influenza/config.py. Section 8 was regenerated on
2026-08-12; the old numbers are in 8b and should not be cited.

Framework: PyTorch Geometric (GCNConv) for run_gnn.py; dense einsum (no PyG) for
run_dualtopo.py.

3. EDGE TYPES
--------------------------------------------------------------------------------
All edges are undirected (added both directions) and every node gets a self-loop
(weight 1.0). Edge construction lives in the "GEO_EDGES / graph" cell of each
notebook. Neighborhood-only edge types loop over indices 0..N_NEIGH-1; anchors
receive geographic edges only.

(1) GEOGRAPHIC ADJACENCY
    Hand-coded neighbor list (GEO_EDGES) from the Boston map: 23 neighborhood-
    neighborhood pairs + 21 anchor pairs (see section 2).
      - PostCovid / CorrBinary: 1-hop only, binary (weight 1.0).
      - MultiEdge: DISTANCE-GRADED by shortest-path HOP count (BFS over
        neighborhood edges only, so anchors are not pass-through shortcuts):
            weight = GEO_DECAY ** (hop - 1),  GEO_DECAY = 0.5,  GEO_MAX_HOP = 3
            => 1-hop = 1.0, 2-hop = 0.5, 3-hop = 0.25  (nearer neighbors dominate)
        Anchors kept at 1-hop, weight 1.0.
        Current counts: 1-hop = 44 (23 nbr + 21 anchor), 2-hop = 29, 3-hop = 22.

(2) CORRELATION / FUNCTIONAL EDGES  (the paper's G_func)
    Pearson correlation of each neighborhood's historical weekly flu series.
      - Computed ONLY on pre-test weeks (dates < TEST_START_DATE) to avoid
        leaking the evaluation period into the graph structure.
      - Threshold CORR_THRESHOLD = 0.85 (Boston neighborhoods are highly
        synchronous; 0.85 keeps the most-correlated ~45% of pairs instead of a
        near-complete graph). Current: 41 undirected pairs.
      - BINARY (CorrBinary): weight 1.0 if r > 0.85 (matches the paper exactly).
      - WEIGHTED (MultiEdge): weight = r (the correlation value itself).
      - Neighborhoods only (not anchors).

(3) DEMOGRAPHIC-SIMILARITY EDGES  ("socio-economic connectivity")  [MultiEdge]
    Gaussian kernel on the 8 static demographic features (static_np):
        D    = pairwise Euclidean distance between neighborhoods
        bw   = median of the nonzero distances (median heuristic)
        sim  = exp(-D^2 / (2*bw^2))
    Edge if sim > DEMO_THRESHOLD = 0.5; weight = sim. Current: 63 undirected pairs.
    Links neighborhoods with similar socio-economic profiles even if far apart.

(4) TRANSIT / MOBILITY EDGES (MBTA)  [MultiEdge]
    Source: Data/MBTA/mbta_adjacency_matrix.csv (14x14, rows/cols already in
    canonical index order). Values = normalized weekly cross-boundary MBTA trip
    volume between neighborhoods. Matrix is symmetrized (max of i,j / j,i);
    edge if weight > 0; weight = MBTA value. Current: 32 undirected pairs.
    Public-transit mobility proxy for disease spread.

(5) UNIFORM COMPLETE (control, ARCHIVED)
    Every neighborhood connected to every other with a flat weight of 1.0 (all 91
    pairs), plus the same anchor edges (weight 1.0). Built to test whether
    STRUCTURE/WEIGHTING helps beyond simply "connect everything equally."

4. PER-NOTEBOOK EDGE COMPOSITION (current)
--------------------------------------------------------------------------------
  PostCovid   : geographic 1-hop binary only.
                26 undirected edges (23 nbr + 3 for the single Background node),
                15 nodes.
  CorrBinary  : geographic 1-hop (binary) + correlation (binary, r>0.85).
                85 undirected edges, 21 nodes.
  MultiEdge   : geographic (multi-hop, graded) + correlation (weighted) +
                demographic (weighted) + transit (weighted), summed into one
                weighted adjacency W. 109 undirected edges, 21 nodes.
                Edge-weight range fed to GCNConv: [0.000, 3.506].

--------------------------------------------------------------------------------
5. WEIGHTING SCHEME (how weights reach the model)
--------------------------------------------------------------------------------
  - MultiEdge / CorrWeighted build an N x N weight matrix W; overlapping edge
    types ACCUMULATE (a pair linked by geo + corr + demo + transit sums to a
    larger weight, up to ~3.5). W is flattened to edge_index + edge_weight and
    passed to GCNConv, which uses edge_weight in its symmetric-normalized
    aggregation (D^-1/2 A D^-1/2). Self-loops = 1.0.
  - The model's forward() threads edge_weight through both GCNConv layers:
        forward(self, x, edge_index, g_vec, edge_weight=None)
    and it is supplied at training, MC-Dropout inference, and gradient-importance.
  - CorrBinary is unweighted (edges present/absent); no edge_weight change needed.
  - NOTE ON VISUALS: the notebook also builds a BINARY matrix "A" (A[i,j]=1 where
    any edge exists) ONLY for plotting. A is not the model input; the graded
    weights live in W / edge_weight (see the weighted-adjacency heatmap).

6. TEST WINDOW & SEASON CLASSIFICATION
--------------------------------------------------------------------------------
  TEST_START_DATE = '2025-05-31'   (one full year back from the end date)
  TEST_END_DATE   = '2026-05-31'
  => Test set spans a full year so it contains BOTH an off-season and a flu
     season. Actual test target dates: 2025-06-01 -> 2026-04-26 (48 weeks).
  Train = all samples before the test window; Val = last 15% of the remainder.

  SEASON SPLIT (classification only; does not change the train/test data):
     Flu season   = target-week month in Oct, Nov, Dec, Jan, Feb, Mar  (26 weeks)
     Off-season   = target-week month in Apr, May, Jun, Jul, Aug, Sep   (22 weeks)
  (End of flu season set to MARCH.) Metrics are reported for flu season,
  off-season, and overall.

Key findings:
  - NOTHING BEATS PERSISTENCE at horizon 1. ARIMA and persistence are
    indistinguishable, and ARIMA's selected orders are mostly (0,1,x) — a
    differenced random walk, i.e. persistence with extra steps. The project had
    no naive baseline before this round, which is why the earlier table read as
    a success story.
  - The relative ordering among graph models DOES reproduce the earlier finding:
    MultiEdge < CorrBinary < UniformComplete < geo-only. Weighting, not mere
    connectivity, is what helps.
  - The new COVID/RSV features are the largest single improvement: MultiEdge
    24.54 -> 16.78 RMSE. Best direction in the repo.
  - MORE HISTORY beats architecture. variant=full (436 weeks) vs post_covid
    (201): MultiEdge 24.54 -> 20.53, Dual-Topo 28.92 -> 19.55.
  - The paper's background-node claim (+0.135 Corr) does NOT replicate:
    dualtopo 0.4169 vs dualtopo_no_bg 0.4122, a 0.005 difference.
  - At HORIZON 2 the graph models close the gap: persistence degrades 15.95 ->
    24.09 while the LSTM reaches 21.54 and gnn_multiedge_leaknorm 22.26.
  - Off-season errors remain ~3x smaller (mean rate ~5 vs ~21 per 100,000);
    off-season MAPE is not a usable ranking metric.

These are not comparable to section 8 for three independent reasons:

  (1) DATA. The loader averaged an ILI visit COUNT row together with the RATE
      row, giving (count + rate)/2 — a per-neighborhood rescaling of the truth,
      about 0.65x for Roxbury. It also imputed suppressed weeks as 0.0,
      inventing ~140 fake zero-rate neighborhood-weeks post-2022. Both fixed;
      see Code/docs/DATA_NOTES.md. This is why the old MAE values look ~35%
      smaller rather than better.
  (2) NORMALIZATION. Statistics were computed over the whole series, test window
      included. gnn_multiedge_leaknorm quantifies the effect: 18.55 RMSE with the
      leak vs 24.54 without. Roughly a third of the apparent quality.
  (3) NO NAIVE BASELINE. Nothing in the old table established that these numbers
      beat "same as last week". They do not.

  Also note the old MAE/RMSE map to scope=pooled, not scope=macro (pooled MAE
  equals macro MAE on a balanced panel, but pooled RMSE does NOT equal macro
  RMSE), while Spearman(nbr)/CCC(nbr) map to scope=macro.

  The raw pre-refactor artifacts are in Code/results/_legacy_pre_refactor/.

11. VACCINATION SIGNAL (weekly) — DATA, METHOD, ABLATION  (added 2026-07)
--------------------------------------------------------------------------------
Goal: give vaccination a weekly resolution (it was a flat per-season constant).

DATA REALITY (Data/Mass Flu Vaccination Data/*.xlsx):
  - Weekly resolution exists ONLY statewide ('Previous Seasons Flu' +
    'Statewide Influenza'): weekly CUMULATIVE % by Total and by group (Age 7 bands,
    Race 8, Ethnicity, Sex). Monotonic uptake S-curve; early weeks censored
    '< 1.0%' (mapped to 0.5%). MA data uses inconsistent casing
    ('Under 5 Years' vs 'Under 5 years') — merged in the loader.
  - Town (Boston) data is SEASONAL only (one cumulative % per season per group).
  - No measured per-neighborhood weekly vaccination exists anywhere.

STEP 1 (implemented, ON): weekly GLOBAL covariate = statewide weekly cumulative
  Total curve, reindexed to week_index (replaces the old flat per-season value).

STEP 2 (implemented, default OFF via USE_VACC_NBR): per-neighborhood weekly node
  feature = sum_over_age-bin( neighborhood age-fraction x statewide weekly rate
  for that bin ). Ecological estimate: contemporaneous statewide weekly age curves
  x STATIC census age mix -> leakage-safe; neighborhoods differ in level AND
  temporal shape via age mix. Global z-scored; anchors get 0.

ABLATION — per-neighborhood feature ON vs OFF (both keep Step 1); MAE:
  Model        overall ON  overall OFF   flu-season ON  flu-season OFF   verdict
  PostCovid      5.60        6.88            8.06           9.90          helps a lot
  CorrBinary     6.09        5.78            8.66           8.25          hurts slightly
  MultiEdge      5.92        5.31            8.38           7.22          hurts

HONEST CONCLUSION:
  - Step 2 (per-neighborhood feature) helps ONLY the bare geo-only model; it HURTS
    the graph-based models (incl. flagship MultiEdge) because the same information
    (age mix, seasonal ramp) is already captured by demographic node features +
    edges + the weekly global covariate. => left OFF by default.
  - Step 1 (weekly global) is mixed: clearly helps CorrBinary (MAE 6.23->5.78),
    ~wash for MultiEdge (MAE 5.53->5.31 but RMSE 9.44->10.06), HURTS geo-only
    PostCovid (MAE 5.98->6.88, Spearman 0.58->0.14). Kept as the more honest
    real-weekly-data covariate, but it is NOT a robust improvement.
  - BOTTOM LINE: on this small post-COVID dataset (~3 seasons), vaccination is not
    a robust predictor at any available resolution; effects are small and
    model-dependent. Flip USE_VACC_NBR on, or revert Step 1 to the flat covariate,
    if a cleaner baseline is preferred.
